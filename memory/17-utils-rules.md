# utils/rules.py — Логика правил замены

**Путь**: `utils/rules.py` (130 строк)

## Что делает

Бизнес-логика для правил замены текста и сопровождающих документов.

## Константы

### DEFAULT_ACCOMPANYING_PREFIXES (14 шт.)

```
"Сертификат", "Паспорт", "Декларация", "Свидетельство",
"Исх. письмо", "Исполнительная схема", "Исполнительная документация",
"Журнал работ", "Акт скрытых работ", "Паспорт материала",
"Протокол испытаний", "Свидетельство о соответствии",
"Декларация о соответствии", "Иной документ"
```

### DEFAULT_REPLACE_RULES

```json
[{"type": "symbol", "from": "_", "to": "/"}]
```

## Ключевые функции

### get_replace_rules() / save_replace_rules(rules)

Чтение/запись правил в state.json.

### get_accompanying_prefixes() / save_accompanying_prefixes(prefixes)

Чтение/запись префиксов в state.json.

### is_accompanying_doc(name) → bool

Проверяет начинается ли имя файла с любого из префиксов (регистронезависимо).

### normalize_name(raw_name) → str

1. Применяет правила замены
2. Если документ сопровождающий:
   - Удаляет всё в скобках кроме "(копия)"
   - Добавляет "(копия)" если его нет

### apply_rules_to_name(raw_name) → str

Применяет **текстовые** правила замены:
- `re.IGNORECASE` — регистронезависимо
- `count=1` — только первое вхождение
- Проверка на дублирование (если `to` уже есть — пропуск)

### apply_symbol_rules(text) → str

Применяет **символьные** правила замены:
- Простая замена подстрок (`str.replace`)

## Поведение

Текстовые правила применяются первыми, затем символьные. Порядок правил важен.
