# routes/materials.py — База материалов

**Путь**: `routes/materials.py`

## Что делает

CRUD для базы материалов (техническая документация с PDF-файлами): добавление, список, поиск, паспорта, просмотр/удаление PDF, полное обнуление раздела.

## Эндпоинты

| Путь | Метод | Описание |
|---|---|---|
| `/api/materials` | GET | Список всех материалов (параметр `q` — поиск) |
| `/api/materials/add` | POST | Добавление материала (multipart) |
| `/api/materials/passports` | GET | Список уникальных паспортов (комбинации полей + единица изм.) |
| `/api/materials/units` | GET | Ранее вводившиеся единицы измерения |
| `/api/materials/pdf/<id>` | GET | Просмотр PDF |
| `/api/materials/reset` | POST | Обнулить раздел (таблица + содержимое папки) |
| `/api/materials/<id>` | DELETE | Удаление материала |

## Форма добавления (POST /api/materials/add)

Поля: `doc_name`, `material_name`, `number`, `date`, `producer`, `arrival_date` (обязательна, `ГГГГ-ММ-ДД` или `ДД.ММ.ГГГГ`), `quantity` (необязательно), `file` (PDF).

- `date` (`дата документа`) — необязательна: чекбокс **«Без даты»**. При пустой дате в имени PDF — токен `без даты`.
- `unit` (`единица измерения`) — необязательна; выпадающий список ранее введённых значений (`GET /api/materials/units`).
- `quantity` — по умолчанию 0,000; вводится с запятой, при потере фокуса форматируется в 3 знака.
- `arrival_date` (дата поступления) — обязательна.
- `file` (сопроводительные документы) — **любой файл** (PDF, фото и др.), **несколько паспортов на один материал**: input `multiple`, каждый файл = отдельная запись в БД со своим порядковым номером (01., 02.…), ответ содержит `count`. Если файлы не прикреплены — чекбокс **«Отсутствует сопроводительный документ»** (вручную, из паспорта не ставится): появляется поле `reason` (обязательно, иначе 400 и красная подсветка), блокируются номер, дата документа и выбор файла; тогда в папке даты создаётся `NN....txt` с текстом причины. Без галочки файл обязателен на стороне frontend.
- **Имя файла**: `NN.Документ;№ Номер;Дата.<ext>` — **материал в имя НЕ попадает**; номер получает префикс «№ » (уже введённый «№» не дублируется), пустой номер → «—», пустая дата → «без даты»
- Форма: радио «Новый паспорт / Из ранее добавленных» (селект паспортов скрыт, пока не выбран второй режим); при выборе паспорта форма СНАЧАЛА очищается, затем заполняется из паспорта (иначе остаются старые значения)
- Таблица: фильтры по всем столбцам (client-side a JS), для дат — дерево Год▸Месяц▸День + сортировка по дате; данные грузятся `GET /api/materials` целиком и фильтруются в браузере.
- ``"`/`"` в наименовании документа/материала/номера на выходе (имя файла) всегда заменяется на `_` (Windows запрещает `/`).

## Хранение

- Файлы сохраняются в `~/Desktop/база материалов/<ГГГГ-ММ-ДД>/NN.Документ;№ Номер;Дата.<ext>` (нумерация с точкой, как в «магии»: `01.`, `02.`, …)
- Материал и единица измерения в имя файла НЕ попадают — хранятся только в БД (в таблице и паспортах)
- Папка = **ISO-дата поступления** (`YYYY-MM-DD`) → корректная сортировка в проводнике (старые → новые)
- `NN` — следующий свободный порядковый номер в папке (`01`, `02`, ...) по порядку добавления; в БД хранится только относительный путь `folder/filename`
- Один и тот же «паспорт» (комбинация полей) можно добавить в новую дату — файл попадёт в папку новой даты с новым номером

## Вспомогательные функции

- `_parse_iso_date(value)` → `ГГГГ-ММ-ДД` (принимает оба формата, иначе `""`)
- `_safe_name(value)` — санитизация имени файла (не Yates-характеры)
- `_next_file_number(folder)` — следующий свободный номер по диску/БД
- `_readable_date(iso)` — `ДД.ММ.ГГГГ` для отображения в таблице

## Поведение

- `arrival_date` обязательна, иначе 400 «Укажите дату поступления...»
- Файлы с потерянными PDF автоматически удаляются из БД
- Поиск по полям: `doc_name`, `material_name`, `number`, `producer`, `date`
- Проверка path traversal при просмотре/удалении
- `reset`: очищает таблицу материалов (только её) и физически удаляет содержимое `MATERIALS_DIR`
