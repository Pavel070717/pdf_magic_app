# routes/rules.py — Правила замены

**Путь**: `routes/rules.py`

## Эндпоинты

| Путь | Метод | Описание |
|---|---|---|
| `/api/replace-rules` | GET | Получить все правила замены (**выдаёт id каждому правилу**: если в state.json правила без `id`, GET проставляет их и сохраняет) |
| `/api/replace-rules` | POST | Добавить правило |
| `/api/replace-rules/<id>` | DELETE | Удалить правило |
| `/api/replace-rules/<id>` | PUT | Изменить правило (type/from/to) |
| `/api/replace-rules/clear` | POST | Очистить все правила |
| `/api/accompanying-prefixes` | GET | Получить префиксы |
| `/api/accompanying-prefixes` | POST | Сохранить префиксы |

> ⚠️ Строки правил имеют **id = hex-строка** (uuid[:8]); во фронтенде в `onclick` id обязательно **оборачивать в кавычки** (`onclick="deleteRule('a8c9d492')"`), иначе `deleteRule(a8c9d492)` → ReferenceError и клик «молчит» — это и был баг с неработающим удалением.

## Что делает

CRUD-операции для правил замены текста в именах файлов и сопровождающих префиксов.

## Типы правил

1. **text** — текстовые замены (regex, регистронезависимые)
   - Пример: замена "Паспорт" на "Паспорт材料" в имени файла
2. **symbol** — символьные замены (простая замена подстрок)
   - Пример: замена `_` на `/`

## Формат правила

```json
{
  "id": "a1b2c3d4",
  "type": "text|symbol",
  "from": "что заменить",
  "to": "на что заменить"
}
```

## Сопровождающие префиксы

Список строк для определения типов документов. Если имя файла начинается с любого из префиксов — документ считается "сопровождающим" и обрабатывается иначе (удаляются скобки, добавляется "(копия)").

Стандартные префиксы: "Сертификат", "Паспорт", "Декларация", "Свидетельство", "Исх. письмо", "Исполнительная схема" и др.
