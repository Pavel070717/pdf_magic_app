# routes/requisites.py — Реквизиты объектов

**Путь**: `routes/requisites.py` (230 строк)

## Что делает

Управление объектами строительства и их реквизитами для автозаполнения формы АОСР.

## Эндпоинты

| Путь | Метод | Описание |
|---|---|---|
| `/api/requisites/objects` | GET | Список объектов |
| `/api/requisites/objects` | POST | Создание объекта |
| `/api/requisites/objects/<id>` | DELETE | Удаление объекта |
| `/api/requisites/<object_id>` | GET | Чтение реквизитов |
| `/api/requisites/<object_id>` | POST | Сохранение реквизитов |
| `/api/requisites/<object_id>/aocr` | GET | Сборка данных для АОСР |

## Структура реквизитов

52 поля, organizovany po gruppam:

### Застройщик (developer)
- Наименование, адрес, телефон, ИНН, ОГРН
- СРО (номер, название, ОГРН, ИНН)

### Подрядчик (builder)
- Наименование, адрес, телефон, ИНН, ОГРН
- СРО (номер, название, ОГРН, ИНН)

### Проектировщик (designer)
- Наименование, ИНН, ОГРН
- СРО (номер, название, ОГРН, ИНН)

### Технадзор (control)
- Наименование, ИНН, ОГРН
- Представитель (должность, ФИО, документ)

### Представители (representatives)
- Заказчик (должность, ФИО, документ)
- Подрядчик (должность, ФИО, документ)
- Проектировщик (должность, ФИО, документ)

## Эндпоинт /aocr

Собирает данные из БД и формирует JSON в формате, ожидаемом `POST /api/aocr/generate`. Вычисляемые поля:
- `builder_continued` = адрес + телефон
- `builder_continued2` = данные СРО застройщика
- `designer_continued` = данные СРО проектировщика
